# CL-Bench 实验中的 Skill

本目录收录三个在部分 CL-Bench 题目上观察到收益的解题候选，以及一个已验证能节省模型调用的轨迹审计插件。三项解题实验使用 Codex 和 GPT-6.1 Sol MAX。表中箭头从普通提示对照组指向加载候选的实验组。这些适用场景在看过结果后识别，仍待在事先选定的新样本上验证。

| 候选 | 观测到的收益 | 同一实验的范围与反例 |
|---|---|---|
| [复用已见表结构](reuse-observed-schema/SKILL.md) | 在 12 个数据库上回答同一类标价比例题，成功 10/12 → 12/12，SQL 查询 29 → 25 次。 | 全轮成功 49/72 → 48/72。另一道迁移后价格字段题成功 10/12 → 7/12。 |
| [复用当前会话的数据地图](recall-observed-data-map/SKILL.md) | 查询办公商品平均评分时，两组均答对 8/8，SQL 查询 19 → 10 次。另一类评分占比题也均为 8/8，查询 18 → 13 次。 | 计划 64 对数据库，8 对完成。已完成部分的总成功数为 35/48 → 34/48。 |
| [定向读取相关源码](read-source-in-context/SKILL.md) | 处理按整数位置取行的同一 issue 时，5 对独立会话成功 1/5 → 3/5，平均原生奖励提高 0.340。 | 84 对计划会话中，37 对在停止前完整封存，覆盖 7 道 issue。总体成功 23/37 → 25/37。余下 6 道 issue 合计两组均为 22/32，平均奖励差为零。 |

## 接入方式

- **复用已见表结构、定向读取相关源码**都是文字 Skill。按任务选择其中一份，在实验组新会话的首个任务提示中加入对应的 `SKILL.md` 正文。存档中记录实际发送的提示，并让对照组使用相同的题目、工具和评分器。
- **会话数据地图**同时需要正文与宿主适配器。冻结实现从同臂、同线程、当前数据版本的既有查询回执重建附录。原实验按轮次保存 `package/` 与 `runs/<panel>/<arm>/cases/`，用 `host.inject(..., record=True)` 挂接提示构造器并保存附录回执。接入已有运行目录时需遵循相同的数据布局。[接入说明](recall-observed-data-map/references/integration.md)
- **轨迹审计插件**在运行结束后读取规范化的双臂决策日志。12 批共 108 例中，每例要求九个字段全部正确。Sol 与本地插件均为 108/108，模型调用从 12 次降到 0 次。验证范围为研究用结构化日志审计，扑克任务的胜率另计。[输入合同与命令](audit-structured-decision-logs/SKILL.md)

## 核验

在仓库根目录运行以下命令即可离线核对四包文件，并用合成数据验证审计插件的成功及缺失结算分支、数据地图的写入与会话隔离。只需要 Python 标准库。

```sh
python -I -B CLbench-Codex/skills/verify_release.py
```

[实验摘要与文件指纹](evidence.json)记录了轮次、协议、聚合指标和原始回执文件的 SHA-256。先逐文件计算 SHA-256，再对按文件路径排序的紧凑 JSON 映射计算包摘要。离线检查覆盖代码版本和示例行为。表中的模型收益来自已封存的历史运行。
