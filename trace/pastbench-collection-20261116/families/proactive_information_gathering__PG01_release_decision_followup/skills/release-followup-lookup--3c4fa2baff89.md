## General policy
For every release follow-up, search session history first using the authorized session_search tool. Before sharing any release guidance, verify the exact reference and exact expiry together against the applicable authoritative record. Reject stale or superseded records as current authority. If either field or the record's applicability cannot be verified, state the uncertainty and do not present the guidance as verified.
## 适用条件
Use when a user refers to a previous release or vendor decision, especially when current notes omit the settled reference or multiple reviews exist for the same product.
## 排除条件
Does not grant new approval, renew expired allowances, or treat a different track's decision as a replacement without evidence. Historical retrieval is distinct from authorization to operate now.
## 操作步骤
1. Search session history first for the exact product or vendor name and identify the release item or track referenced by the user. Use only the authorized session_search tool to retrieve history.
2. If the requested note is available, inspect it for scope and missing decision details; a current title or tag does not establish that it contains the authoritative record.
3. Compare candidate records by item, track, and stated authority. Exclude incomplete shells, recaps, superseded archives, and unrelated one-off allowances as substitutes for the settled decision.
4. If broad results are ambiguous or incomplete, refine the query using scope or decision terms and retrieve the exact candidate session before selecting it. Do not choose solely by recency or reference number.
5. Before sharing release guidance, verify the exact reference, approval status, allowed environment or activity, and exact expiry together from the applicable authoritative record; do not combine fields from different decisions or infer missing expiry details.
6. Reject stale or superseded records as current authority. For a requested historical decision, preserve its original expiry and distinguish an expired allowance from permission to operate now.
7. Only after verification, share the requested release note or summary with the specified recipients when sharing is authorized. Do not forward an incomplete shell as though it were the settled decision.
8. Confirm the share result and report the recovered fields in the user's requested format without implying broader approval or an extended expiry.
## 验证
- Session history was searched first.
- The selected record matches the requested item and track and is not merely a current-looking shell or an unrelated newer allowance.
- The exact reference and exact expiry were verified before sharing release guidance.
- Reference, status, environment or activity, and expiry are supported by the same applicable record; expiry is not silently extended.
- Stale or superseded records are rejected as current authority.
- Any claimed sharing is supported by a successful share result for the requested note and recipients.
