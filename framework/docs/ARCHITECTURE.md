# 架构与信息边界

## 一题的时间关系

1. 从公开题单取得任务和工作区，保存公开输入SHA，冻结当前技能版本。
2. 执行器在任务环境中运行，按公开内容自主使用工具与技能。
3. 结束后核对工具返回，封存公开轨迹及工作区，并核文件清单。
4. 从同一执行记录分别启动管理器与独立评分器。评分器拿单独的工作区副本，修改私有答案或延迟评分不会改变管理器消息，也不阻塞下一题。
5. 管理器Read证据和父技能，直接提交实际结构化参数，宿主校验并原子写库，当场返回真实commit或拒绝。
6. 下一题使用新快照。离线Judge关联当题实际使用的旧版本，先判采用，再结合客观结果判观察性效果。

一个实验序列的执行和库编辑保持串行，以固定版本关系。独立客观评分可并行，题目所属族、来源和预标适用性不进入工具路由。

## 数据合同

|对象|允许内容|保存位置|
|---|---|---|
|Task|原始公开id、instruction和public_dir|题单与公开工作区|
|Execution|实际模型消息、工具调用/返回、最终文本及环境身份|episodes/id/actor与execution.json|
|Snapshot|稳定ID、版本SHA、名称、描述和全文|episodes/id/snapshot.json|
|Curation observation|公开任务、闭合事件、原父项全文、封存产物索引|curation-observation.json|
|Objective|score 0/1/null与benchmark自定义details|evaluation/id/objective|
|Review|采用判断、证据索引、局部/整轨原分、校准信用|evaluation/id/review|

管理器的Read只允许索引中的固定文件路径，工具集中没有Bash或任意文件读取。评分器、答案、私有错误字段及Judge结果没有进入该路径集合。公开数据本来包含名为score的业务字段时，仍完整保留。

这里的隔离由权限分工、观察构造和工具白名单实施。管理器只有受控模型工具，benchmark宿主插件属于受信任代码，部署者仍需为数据和插件配置系统权限。

## 唯一事件来源及正文证据

文件工具入口保存模型响应与每个真实调用/返回。原生Claude入口保留SDK JSONL，同时按同一合同导出事件。每项曝光证明绑定稳定Skill ID、版本SHA、工具ID、非错误完整返回，以及后来一份实际完成的模型请求。

原生Read会带行号，审计只移除已识别的SDK行号，核完整原正文进入了同工具ID的真实后续请求。缺字、错工具ID或只有目录均不能通过。采用还需对应正文曝光之后的Write、Edit或Bash业务动作。

## 库的修改

沿用已有原子事务实现。变更支持零到多项，更新保留父名称和稳定ID；合并/拆分/归档保留旧正文blob。修改父项前必须完整Read。提交核父状态SHA、实际已读事件、字段、重名、重复正文及依赖DAG。冲突和原候选保存在磁盘。

事务工具返回前已执行实际提交。字段错误、业务规则拒绝与上游请求错误各留原证。整个事务再次提交须与原意图完全一致，已提交事务可以幂等回读。

结构检查无法保证技能语义正确、适用范围未退化或有未来效益。这些需要后续消费者及相应研究设计验证。

## 评审与奖励

- finding输入公开题、目标确切正文、曝光事实、事件及其他可用技能，输出采用状态与动作索引。
- effect在finding基础上加入独立客观结果。`alternative_explanations`与`uncertainties`统一为字符串数组，提示与校验采用同一类型合同。
- 原始局部分、整轨分为−2至+2或null，各Skill及两个评分轴不相加。
- 客观失败时，整轨正训练信用上限为0。客观结果未知时，训练信用为null。因果奖励始终为null。
- 原候选无效时保存并输出null，不通过重新采样追求有效或正分。

框架导出的`training_credit`仅是当前固定权重系统的观察性训练信号，不能直接视为编辑因果收益。梯度训练、权重同步与训练算法由外部优化器负责。

## 预算与真实费用

执行器默认64次生成、900秒；管理器默认16次生成、900秒。每角色按已观测usage控制1M输入和65536输出，下一请求的max_tokens被剩余输出预算限制。输入usage只能在完整响应后得知，若超限则保留该响应并阻止其工具执行。服务端精确输入token预检可由具备相同tokenizer的模型适配器补充。

usage缺失时保留null及已知下界，生成次数和墙钟约束仍生效。每次模型请求按实际路径去重分角色统计，金额保持null，不将CLI估算当账单。
