# 用 Codex 从任务里生成 harness 扩展

选择一条已经采集的任务，让本机 Codex 自行读取轨迹文件，寻找值得复用的经验，再写成可独立安装的候选扩展。一次运行可以生成零个、一个或多个候选，结论保存在 `REPORT.md` 中。

## 开始分析

先确认本机 Codex CLI 已能正常使用，然后打开安装包的工作台。

```sh
skill-rsi ui
```

1. 左侧选择任务所在的框架，在任务记录中找到并打开主会话。可按主题或工作目录搜索。
2. 在“Codex 生成 harness 扩展”中填写可选的补充要求，例如“关注多次返工时哪些约束被遗漏”。
3. 默认使用 `gpt-6.1-sol` 和 `ultra`，也可以修改本次模型和推理强度。
4. 点击“一键分析生成”，查看运行进度、诊断和本次生成目录。

生成组件使用本机 Codex 已有的账号与模型服务配置。CLI 路径及默认模型可在“Codex 默认设置”中保存，这份设置由生成组件单独管理。

## 查看生成结果

Codex 可以自己查看主会话、工具结果和内部子任务的轨迹文件，提出适合这次经验的实现。报告和候选文件保存在界面显示的生成目录中。

生成任务在后台继续运行，关闭页面也会自动校验、打包。重新打开工作台后，会恢复尚未收尾的任务。界面依次显示模型运行、校验打包和最终结果；过程中某条命令失败后被模型修正，会作为诊断保留，最终结果另行显示。

完成后展开“阅读生成报告”，查看发现了什么、依据是什么，以及哪些情况仍待验证。候选卡片列出功能、分类、版本、形式、README 摘要和制品校验结果。展开“适用范围与文件”可查看适用和跳过条件、声明宿主，以及源码、ZIP 和分析报告的完整位置。路径均可复制，也可以点击“打开位置”在本机查看。校验失败时会显示具体原因。零候选的运行也会保留报告。

## 人工审阅后使用

阅读候选 README 和实现，确认它能做什么、何时触发、何时跳过，以及效果判断有哪些任务依据。制品校验用于检查包的格式和文件完整性，实际效果由后续任务验证。

决定试用时，点击该候选的“安装候选”。再到目标框架的扩展列表，选择模式、打开开关并保存接入。可以先用 `shadow` 查看它会采取什么动作，再按宿主提供的能力决定执行方式。[工作台的扩展管理](04_本机工作台.md)

API 模型和本机规则仍可从“高级分析入口”选择，各自的设置在该入口中管理。
