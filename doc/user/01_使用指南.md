# 统一 CLI 使用指南

在主仓根目录用 Python 3.11+ 执行 `python -m pip install -e .`，或从发行 wheel 安装 `skill-rsi`。从任意目录执行 `skill-rsi --help`。需要 YAML 配置时安装 `skill-rsi[yaml]`。本机制品和项目账本可通过 `SKILL_RSI_HOME` 或全局参数 `--state-dir` 指定。

## 为现有项目安装策略

下面以 DSH 为例。在目标项目中配置一次适配器，再用一条普通任务确认当前 CLI 实际送达的节点。DSH 使用已安装的 SDK Profile。

```sh
skill-rsi setup --host dsh --project .
skill-rsi collect --host dsh --project . --prompt '读取当前项目的一份说明文件并总结。'
skill-rsi doctor --host dsh --project .
skill-rsi artifact builtin tool-result-view --output /tmp/tool-result-view.zip
skill-rsi artifact builtin constraint-check --output /tmp/constraint-check.zip
skill-rsi artifact install /tmp/tool-result-view.zip
skill-rsi artifact install /tmp/constraint-check.zip
skill-rsi project enable tool-result-view@1.0.0 --host dsh --project . --mode shadow
skill-rsi project list --host dsh --project .
```

`doctor` 显示已注册、实际回调、能力和绑定修订。试跑会记录拟采取的动作。建议模式需要宿主的展示节点，执行模式需要包声明的写入或读取能力。策略启停在宿主确认的边界生效。Claude Code 和 Codex 使用同一个入口，分别传 `--host claude_code` 或 `--host codex`。两者需要按其原生 CLI 确认项目的 hook 和 MCP 配置。Codex trace 可通过 `collect --trace` 为所选进程开启。用 `project receipts` 读取试跑和交付记录。用 `project expand HANDLE` 读取当前项目仍在保留期内的原件。

用 `setup --config` 登记核验包允许读取的来源。每条 `constraints` 指定项目相对路径、对象、字段，以及可选 JSON Pointer。字段来源由项目明确授权。只有当当前宿主边界能关联到依赖该对象和字段的动作时，核验才会介入。DSH 托管启动可在采集配置中设置 `query_source`，把本轮查询关联到一个已注册的项目相对路径。[配置示例](../../configs/setup-dsh.example.json)

```sh
skill-rsi project enable tool-result-view@1.0.0 --host dsh --project . --mode apply
skill-rsi project enable constraint-check@1.0.0 --host dsh --project . --mode apply
skill-rsi project disable tool-result-view --host dsh --project .
skill-rsi doctor --host dsh --project .
```

升级先安装新版本，再显式绑定该版本。回退时重新绑定上一版。卸载制品前检查 `artifact list` 的引用。禁用项目绑定并等宿主确认后，可用 `uninstall --host dsh --project .` 撤销宿主注册。

## 观察、归档和提炼

`skill-rsi attach --host dsh --project . --mode observe` 单独开启观察。完成任务后用 `doctor` 获取该宿主的 journal 路径，再用 `archive-journal JOURNAL --output ARCHIVE` 发布。托管采集可传 `collect --output CAPTURE --archive ARCHIVE`。原生历史可用 `import SOURCE --host dsh|claude_code|codex --format FORMAT --output ARCHIVE` 导入。来源和配置参数以 `skill-rsi import --help` 为准。

```sh
skill-rsi verify ARCHIVE
skill-rsi inspect ARCHIVE
skill-rsi inspect ARCHIVE --run-id RUN_ID --view observations
skill-rsi review ARCHIVE --config REVIEW.json --purpose discovery --output SNAPSHOT.json
skill-rsi extract SNAPSHOT.json --id candidate-study --teacher TEACHER.json --output DISCOVERY
```

审核配置用 `run_groups` 映射拆分、组和 run ID。先登记 `development` 与 `holdout`，发现只读取开发组。默认使用索引元数据。要提供事件正文，按 `payload_allowlist` 登记 `run_id`、`event_id`、引用字段和 SHA-256。模型配置使用环境变量名读取密钥，实际凭据由操作者在本机设置。[模型配置示例](../../configs/teacher.example.json)

发现产物中的候选仍需独立验收。审核 `SKILL.md` 后，配置 `approved_sha256` 和 `review_ref`，使用 `skill-rsi materialize EXTRACTION COMPONENT VERSION --config REVIEW.json --output CANDIDATE.zip` 生成独立制品。候选包含声明式 `implementation.json` 时，审核配置还须提供 `approved_configuration_sha256`。已有策略代码和清单可直接使用 `skill-rsi artifact pack SOURCE --output CANDIDATE.zip`。

## 比较策略与交接数据

`benchmark tasks --config BENCHMARK.json` 列出任务及其指纹。工作区评分器版本是 `workspace@<fingerprint>`，CL-Bench 使用 `clbench@<revision>`。以 `review --purpose evaluation` 冻结留出材料，使用实验配置固定宿主版本、模型、种子、预算和包摘要。

```sh
skill-rsi experiment freeze HOLDOUT.json --config EXPERIMENT.json --benchmark BENCHMARK.json --output PROTOCOL.json
skill-rsi experiment run PROTOCOL.json --benchmark BENCHMARK.json --capability-project PROJECT --output RUNS
skill-rsi experiment report PROTOCOL.json RUNS --output REPORT.json
```

任务历史产生的候选应向 `experiment freeze` 传入 `--discovery EXTRACTION`，以查验发现开始前登记的留出范围。报告保留缺分、漏载、跳过和未确认的交付。DSH 的日志对照可选 `native`、`model_tools`，以及绑定 `projection: "fixed"` 的日志包和冻结候选。双包对照由同一协议分别分配两包停用、单包启用及双包启用。

`skill-rsi export SNAPSHOT.json --dataset-id ID --score-protocol PROTOCOL --output BUNDLE` 交付明确按训练用途授权的可恢复状态、来源索引和散列清单。训练端可使用独立项目的评分及 replay 流程。[训练交接](../contributor/04_离线训练交接.md)
