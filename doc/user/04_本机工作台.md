# 本机工作台

安装 wheel 后运行 `skill-rsi ui`，浏览器会打开本机管理页面。工作台使用已安装的 DSH、Codex 和 Claude Code CLI，以及各自已有的模型配置。

```sh
conda activate skill-rsi-dev
python -m pip install --upgrade /path/to/skill_rsi-0.5.1-py3-none-any.whl
skill-rsi ui
```

保留启动界面的终端。以后打开工作台只需执行最后一条命令。工作台帮助你维护长程任务的记忆策略，日常任务可以继续在原生助手里完成。

## 在 DSH 桌面端继续长程任务

1. 在工作台选择项目目录，左侧选 DSH，接入方式选“桌面端”。
2. 勾选记录轨迹，选好本项目要用的扩展，点击“接入桌面端”。
3. 完全退出并重新打开 DSH 桌面端，选择同一个项目工作区，照常发起或继续任务。
4. 回到工作台，在任务记录中打开这个会话。新增的会话活动会持续写进同一个任务目录。

桌面插件按项目路径识别会话。扩展在该宿主提供的事件节点运行，保存配置后可从加载状态和具体动作记录核对。首次人工试用时，先选试跑模式，观察它在什么情况下建议保存、取回或核对信息。

例如任务实际在 `/Users/you/Desktop/demo` 工作区执行，工作台也应接入这个目录。加载状态说明插件已启动，任务目录中的 `session-events.jsonl`、`tools.jsonl` 和 `calls.jsonl` 持续增长，才说明这个会话正在采集。

## 先用 DSH 跑一个任务

1. 在页面上填入已有项目的绝对路径，点击“打开项目”。
2. 左侧选择 DSH。CLI 路径可用自动找到的结果，Profile 使用 `sdk`。
3. 勾选“记录任务轨迹”，启用 `tool-result-view`，先选择“试跑”模式，点击“保存并接入”。
4. 在任务框输入“请读取项目的 README.md 并用三句话概括”，点击“运行任务”。这一步会调用 DSH 当前配置的模型。
5. 在任务列表点击该任务，查看执行输出、错误信息和保存目录。

DSH 通过托管 SDK 启动，项目插件随启动加载。长日志策略默认查找至少 60 行成功文本结果中的错误词。想试这项能力，可以让助手执行 `seq 1 100 && echo ERROR`，再查看试跑记录。改为“执行”模式并保存后，符合条件的结果会使用短视图。

## 继续使用 Codex CLI 或桌面端

1. 左侧选择 Codex，在“记录本机全部 Codex 主会话”区域确认目录，默认是 `~/.codex`。
2. 点击“开始记录新数据”，一次开启本机所有项目的原生会话记录。
3. 保留工作台运行，照常在 Codex CLI 或桌面端继续任意项目的任务。无需重启 Codex。
4. 回到任务记录，查看新增会话活动。一条主会话一个文件夹，内部子任务并入主会话，用户独立分叉的会话单独保存。

首次开启会以已有文件末尾建立起录基线，此后只记录新内容，现有会话也可继续使用。工作台每 2 秒检查一次，显示起录时间、最近检查时间、已录主会话数和错误原因。“等待新数据”表示已准备好，“检查新数据”可手动检查。重启工作台保留读取进度，全局停止后重新开启会跳过停用期间的数据。上方项目目录用于扩展配置和列表筛选，原生记录覆盖本机所有 Codex 项目。

起录后的原生事件保存在任务目录的 `capture/codex-rollout.jsonl`。旧会话在起录后产生新内容时才会出现，识别会话所需的旧元数据作为上下文保存。可见的新增活动可在详情中查看并交给 LLM 分析。喜欢终端操作时，也可以保留 `skill-rsi record --host codex` 持续运行。[录制命令与状态查询](02_Codex使用指南.md)

## 在 Codex 或 Claude Code 中使用扩展

在左侧选择对应宿主，为同一项目选择它要使用的扩展，再点击“保存并接入”。每个宿主分别保存启停和模式。切换页面后，任务也由当前选中的宿主执行。

Codex 的日志示例通过 `skill_rsi_read` MCP 工具读取项目文件。在“高级配置”中填写 `mcp_paths` 后保存，再让助手明确调用这个工具。Claude Code 通过工具和会话回调运行策略，也可使用自有 MCP。两端首次使用时，按原生 CLI 的提示完成项目授权。[Codex 示例](02_Codex使用指南.md) · [Claude Code 示例](03_ClaudeCode使用指南.md)

## 安装和管理扩展

“添加扩展”可以安装随框架交付的策略，也可填写本机 ZIP 或扩展目录路径。框架生成的 ZIP 与外部导入的 ZIP 使用同一入口。安装后，打开所需宿主的开关，选择模式并保存。

每张扩展卡显示功能和分类，展开“适用范围与文件”可查看适用场景、跳过条件、声明宿主、校验状态，以及源码、安装、ZIP 和报告位置。路径可完整阅读、复制，或点击“打开位置”在本机查看。外部包缺少说明时会标为待补全。

- **试跑**记录策略会采取的动作。
- **提示**向用户展示建议，需要宿主支持展示节点。
- **执行**在宿主提供相应能力时交付动作。

关闭某个扩展的开关并保存，即可停用。页面上的“等待回调”表示已保存配置，“已生效”表示宿主已经确认该版绑定。任务记录保留具体动作与失败原因。

## 任务轨迹放在哪里

本机的新数据统一保存在 `/Users/user1/SkillRSI/tasks/`。记录按宿主、来源和任务分层，同一会话持续写入同一个任务目录。来源可区分 `cli`、`desktop`、`managed` 等，文件夹名包含日期、主题、工作目录名和短 ID，任务内部的稳定编号用于查找记录。

```text
/Users/user1/SkillRSI/tasks/<宿主>/<来源>/<日期>_<主题>_<工作目录名>_<短id>/
├── task.json          # 项目、宿主、任务内容与完成状态
├── capture/           # 原生启动记录、输出和错误
├── journal/           # 采集到的事件与扩展动作
└── worker.log         # 托管进程诊断
```

可用的事件和文件取决于采集入口和宿主记录。Codex 日常任务列表按主会话展示起录后的数据，内部子任务存放在同一目录的 `capture/threads/`。页面中的“停止任务”会请求结束工作台启动的任务，已经执行的项目操作和记录可在目录中核对。

## 分析任务，生成记忆管理扩展

任务列表显示当前宿主下所有项目的主会话，每条都带项目和来源。可以按主题、完整工作目录或来源搜索，勾选“仅当前项目”可缩小范围。打开任务详情，在“Codex 生成 harness 扩展”中点击“一键分析生成”。

默认由本机 Codex 使用 `gpt-6.1-sol`、`ultra` 自行读取任务轨迹文件，寻找经验并实现零个或多个候选扩展。可以填写补充分析要求，修改本次模型或推理强度。页面持续显示进度、诊断和生成目录，完成后可阅读 `REPORT.md` 与各候选的 README。[Codex 一键生成教程](05_Codex一键涌现扩展.md)

人工检查候选的功能、触发、跳过条件和效果依据，再决定是否“安装候选”。安装后，在目标宿主的扩展列表手动启用并保存接入。候选卡片显示制品校验结果和错误，实际效果由后续任务验证。

“高级分析入口”保留 API 模型与本机规则。API 格式、地址、模型和本机密钥文件可在其中的“LLM 配置”维护。
