# 06　接入自己的数据、宿主和 benchmark

手里有旧会话，先按文件格式选择读取器。想记录今天正在做的任务，就把适配器接到本机宿主。要比较两项策略谁做得更好，再给任务配上能复位的环境和评分器。三个入口可独立贡献，最终用同一份公共事件契约交换记录。[输入格式兼容表](02_轨迹数据契约.md#输入格式兼容表) · [总体架构](01_总体方案与架构.md)

| 要解决的问题 | 对应接口（规划） | 最小验收 |
|---|---|---|
| 从哪里读，读到哪一条 | `DataSource.read(cursor)` 返回原始记录、来源位置及下一游标 | 从上次位置重读时，同一原生事件只登记一次。 |
| 原生事件是什么意思，宿主允许做什么 | `HostAdapter.decode` 解码历史，`attach` 接新事件，`capabilities` 声明能力，`deliver` 返回执行回执 | 给同一宿主一条历史事件和一条在线事件，能对齐身份，能说明各自观察到了哪一层。 |
| 如何重做任务，怎样判分 | `BenchmarkAdapter.tasks / reset / step / score` 提供题目、初态、交互和原生评分 | 同一初态能重新运行，结果可追溯到具体实例及评分器版本。普通项目可以没有 benchmark。 |

## 导入历史数据的三种方式

1. **直接读取标准格式。** 已有 `SkillRSI-CTX-v1` 归档时，读取批次索引和各运行目录，校验事件的原件引用与摘要。新接入的标准事件按契约提供项目、运行、事件身份、来源位置和可见范围。[标准归档的文件树](02_轨迹数据契约.md#标准归档的文件树)
2. **用配置映射字段。** 如果本地 JSONL 只是列名和事件类型不同，提交字段映射及一行合成样本即可。映射负责解释内容，读取器负责记录文件位置和内容摘要。
3. **提供外部读取器。** 分片数据库、压缩包、会轮转的日志或增量流可以贡献独立读取器。附上从头读取、从游标续读和遇到半条记录的测试。涉及宿主协议的线程、工具调用或返回值，交给对应宿主适配器解码。三条路径借鉴了 ms-swift 从标准文件、声明式映射到自定义加载的设计。[ms-swift 自定义数据集](../../../ms-swift/docs/source/Customization/Custom-dataset.md)

### 示例：把一行本地日志映射成恢复事件

假设工具导出的 `events.jsonl` 第一行如下，字段 `id` 在本次运行内唯一。

```json
{"project":"demo","run":"r7","id":"e12","seq":12,"kind":"resume"}
```

下面是**拟议的映射配置示例**。字段映射按“公共字段 → 源列名”书写。

```yaml
source:
  path: ./events.jsonl
  source_id: demo-export
  mapping:
    fields:
      project_id: project
      run_id: run
      event_id: id
      seq: seq
      type: kind
    values:
      type:
        resume: session_resumed
```

预期得到项目 `demo`、运行 `r7` 的事件 `e12`，顺序为 `12`，类型为 `session_resumed`。读取器补上契约版本、来源 `demo-export`、第一行的定位与摘要、下一游标和可见层“导出日志”。这行只证明记录到恢复，模型随后看见什么及任务得分均未知。去掉原生 ID 时，读取器需提供稳定的来源身份和不可变位置；文件轮转后先核对分段及已读前缀，再续读。

## 接到本机正在使用的宿主

1. **确定范围。** 用户选择项目、宿主、数据来源及允许保存的字段。已经结束的区间从获准的会话文件回填，读取历史可以在原宿主关闭时进行。记录缺失的区间。
2. **开始观察。** 探测版本、可用工具和能观察的节点。按宿主接入方式注册 hook、插件或网关。某些入口要到下一会话或重载后才生效。记录第一条真正到达的新事件，声明从这里起覆盖实时运行。
3. **核对边界。** 新开一个测试任务，执行一次可辨认的读取，关联原生调用 ID、工具结果和可得到的后续回执。找到对应主请求，可以确认资料出现在该层输入；实际发送和任务采用另取证据。事件和原件落盘后再提交游标，回填与实时重叠时按同一原生身份去重。
4. **按项目选择用途。** `observe` 只控制轨迹采集。已有策略包可分别选 `shadow`、`suggest`、`apply`。先在试跑记录中核对拟采取的动作，在隔离任务上验证实际执行回执。缺少写能力的宿主仍可贡献历史解析和只读采集能力。

### 按宿主做第一次验收

从自己使用的宿主选一行。中列对应现在可运行的参考样例，右列是迁入用户项目后，首次声称该能力生效时要看到的结果。

| 宿主 | 先复跑哪个样例 | 在自己的项目核对什么 |
|---|---|---|
| **DSH** | 在参考仓跑工具视图测试，先聚焦长输出的几行，再恢复全文。对已有批次运行 `evidence build` 和 `evidence verify`，从一条请求引用读回 SDK 参数。[命令与预期](adapters_doc/dsh/README.md#现在可复跑) | 确认插件在当前 query 的主调用生效，辅助调用维持原有输入。若只接了 query 前策略，就在这个边界记录触发、跳过与超时回退。 |
| **Claude Code** | 跑长链与模拟网关测试，检查压缩前后快照和一次请求对应的转发回执。[命令与预期](adapters_doc/claude_code/README.md#现在可复跑) | 在所选项目和 CLI 版本各试一次成功与失败的工具调用。成功时按工具 ID 核对短视图及可展开的原件；失败时核对原生错误。恢复场景再验证检查点是否属于同一会话。 |
| **Codex** | 先确认 `codex debug trace-reduce --help` 可用，运行离线夹具。完整样例可定位工具结果进入第二次逻辑请求，缺少收尾和缺少请求正文有不同结果。[原生轨迹离线验收](adapters_doc/codex/原生轨迹离线验收.md) | 深度记录需把 `CODEX_ROLLOUT_TRACE_ROOT` 传到实际启动会话的进程，确认本次生成了 bundle。旧会话只有 CLI 或 MCP 回执时，仍可接入这部分历史，并标明缺少哪次主请求。[Codex 启动与补录](adapters_doc/codex/README.md) |

三端都可以用本地合成任务验收。比如让工具读回“接口单位已改为秒”，然后核对助手下一次换算的实际参数。没有评分器时，把这个断言和出处作为项目反馈；要比较不同策略的收益，再给各组接同一个可复位的任务和评分器。[轨迹文件与证据层级](02_轨迹数据契约.md#三种宿主的原始文件)

## 换一套 benchmark，保留同一宿主和策略

| 环境 | 复位与执行 | 如何评分 |
|---|---|---|
| 自己的工作区题单 | 参考题 `sum-1` 把公开的 `input.json` 复制到干净目录。两组分别用相同输入，要求把 `[2, 4, 8]` 求和，写入 `output/result.json`。 | 外部评分器独立读取提交物，与期望的 `{"sum":14}` 比较。这个公开例子演示判分约定；运行时只将题面和公开目录交给执行器。参考实现区分合格、按题规判零和评分器故障时的缺分。[题目与公开输入](../../../Skill_RSI_chengze/framework/examples/tasks.json) · [评分实现](../../../Skill_RSI_chengze/framework/skillrl/benchmarks.py) |
| CL-Bench 连续任务 | 固定任务版本、seed、实例顺序和初始记忆，从同样的 schedule 独立启动各组，再由宿主交付同一版本的策略。 | 从 `TaskResult.instance_outcomes` 取各实例的原生 reward 与可用的任务指标，保留原始量纲及评分出处。跨实例持续的会话按完整序列配对。[原生结果接口](../../../continual-learning-bench/src/interface.py) |

WorkBuddy 布局由参考导出器提取公开题面和工作区文件，私有验证材料留在评分端。自定义 benchmark 可以提供自己的 verifier，把缺少提交物、断言失败和评分服务报错区分开。[参考评分协议](../../../Skill_RSI_chengze/framework/docs/BENCHMARKS.md)

## 从主仓根目录复验

以下命令从 `Sklii_RSI_master/` 执行，要求同一工作区中存在相邻参考仓，使用 Python 3.11+。第一条预检应返回 `tasks=1`、`model_calls=0`。第二条用本地合成任务核对外部 verifier 和导出时的私有答案隔离，预期两项测试通过。上述映射和统一实时接入仍是主仓待开发接口。

```bash
(cd ../Skill_RSI_chengze/framework && python -B -m skillrl examples/local.json --check)
(cd ../Skill_RSI_chengze/framework && PYTHONPATH=tests python -B -m unittest \
  test_framework.FrameworkRounds.test_round_11_workbuddy_native_verifier_contract \
  test_framework.FrameworkRounds.test_round_15_workbuddy_export_keeps_private_grader_out)
```

贡献 PR 时选一个入口，带上一份可公开的最小输入、期望事件或分数，以及一个失败样例。来源映射的 PR 可通过读取器独立验收，宿主 PR 还要有本端观察或执行回执，评测 PR 要说明如何复位和复算结果。维护目录与评审人见[开发分工与 PR 规范](05_开发分工与PR规范.md)。
