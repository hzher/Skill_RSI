# 开发分工与 PR 规范

先按变更的对象找负责人。改 Claude Code 怎样接收工具结果，找 **yangyang**。改 Codex 怎样续接会话，找 **yifan 和 chengze**。改三个宿主共用的事件字段、数据接入或其他宿主，找 **hzh**。

## 主仓允许改哪些目录

本表的路径都相对于 `Sklii_RSI_master/`。当前交付的是开发前文档，主仓代码目录按下表规划，第一份实现可以新建自己范围内的目录和文件。文末列出的相邻原型已有实现和测试，可用于核对行为。

| 负责人 | 负责的调用链 | 宿主 PR 允许修改或新增 |
|---|---|---|
| **yangyang** | Claude Code 的会话读取、hook、MCP 或已配置网关的适配、加载与停用回执 | `skill_rsi/adapters/claude_code/`、`tests/adapters/claude_code/`、`doc/contributor/adapters_doc/claude_code/`。[Claude Code 方案与验收](adapters_doc/claude_code/README.md) |
| **yifan、chengze** | 共同负责 Codex。现有分工可由 yifan 优先接 Responses API 和 MCP 工具，由 chengze 优先接账号 CLI、宿主事件和会话续接。原生轨迹解析或交叉需求由两人指定一人负责整条调用链，另一人审查或补独立回归。 | 两人共用 `skill_rsi/adapters/codex/`、`tests/adapters/codex/`、`doc/contributor/adapters_doc/codex/`。按入口增补模块。[Codex 方案与验收](adapters_doc/codex/README.md) |
| **hzh** | DSH、新宿主及其余兼容工作，负责共享接口与主包集成 | DSH 使用 `skill_rsi/adapters/dsh/`、`tests/adapters/dsh/`、`doc/contributor/adapters_doc/dsh/`。新宿主按同一结构增加子目录，共享模块走共享 PR。[DSH 方案与验收](adapters_doc/dsh/README.md) |

宿主测试的合成输入放在各自的 `tests/adapters/<host>/fixtures/`。例如，yangyang 可增加一个“成功工具返回过长”的输入，测试短视图和原件引用。只增加 Claude Code 的测试用例，无需修改 Codex、DSH 或评分器。

| 共享 PR 的变更 | 主仓规划位置 | 审查与验收 |
|---|---|---|
| 事件、证据、版本和回执字段 | `skill_rsi/contracts/`、`skill_rsi/evidence/` | hzh 协调受影响宿主。验证旧记录可读、缺字段有说明，附输入和输出对照。 |
| 数据来源、字段映射和 benchmark | `skill_rsi/sources/`、`skill_rsi/benchmarks/` | 本地来源可以不带评分。benchmark 自行提供任务与评分，提供一个替换来源或评分器的例子。 |
| 候选发现、独立策略包、项目启停及评测交接 | `skill_rsi/discovery/`、`skill_rsi/components/`、`skill_rsi/runtime/`、`skill_rsi/experiments/`、`skill_rsi/exchange/` | 验证候选与评分数据隔离，停用一包后同项目其他包仍可运行。 |
| 统一命令、打包配置及跨宿主规范 | `skill_rsi/cli/`、`pyproject.toml`、根目录或 `doc/` 下的公共文档 | hzh 负责集成。影响某个宿主时，请对应负责人复核实际入口和回执。[总体方案与架构](01_总体方案与架构.md) |

共享模块的测试放在对应的 `tests/<模块名>/`。例：`skill_rsi/sources/` 的字段映射测试放入 `tests/sources/`。

## 跨目录需求怎样拆

**例：给 Claude Code 增加“结果已截断”的记录。** yangyang 先检查公共契约已有的可见范围、缺失原因是否能表达这个事实。能表达，就在 Claude Code 适配器做映射并补测试。若需要新增所有宿主都看得懂的字段，则由提议者与 hzh 协作开共享 PR，说明旧输入怎样读取，用一条合成记录固定预期行为。宿主 PR 引用这条变更，负责把 Claude 的事件接进去。Codex 端是否能看到截断边界，由 yifan、chengze 在自己的适配器独立验证。[轨迹数据契约](02_轨迹数据契约.md)

## PR 允许与严禁的操作

| 允许 | 严禁 |
|---|---|
| 在负责的目录内补实现、兼容分支、合成样例、测试和使用说明。修复回归时带上能重现问题的旧输入。 | 在单宿主 PR 顺手重命名公共字段、改其他宿主目录、替换默认评分口径，或夹带无关的格式化和批量删除。 |
| 在自己的工作分支追加提交，解决与目标分支的冲突，保留其他贡献者已经合入的行为。 | 绕过 PR 直接覆盖主分支，强推共享分支，或删除他人的工作分支。 |
| 用临时工作区模拟安装与撤销。只更新本项目登记的配置项，回滚时核对原内容和其他项目的引用。 | 覆盖用户已有配置、删除同事未提交的文件、更改其他项目的绑定，或在卸载时清空共享配置及历史记录。 |
| 提交合成或获准公开的最小样本、复现命令和预期回执。来源、宿主和评分器通过接口装配。 | 提交账号凭据、个人会话原件、私有日志、私有数据集和运行目录；在宿主代码中硬编码题目、数据路径或标准答案。 |
| 如实记录失败、未知、缺少的能力和未跑的测试。效果报告绑定实际执行版本，并在留出任务验收。 | 向提炼模型或运行中策略暴露隐藏答案、未来反馈或留出数据，删除失败样本，或用安装成功、模拟回执替代真实任务收益。 |

## 外部开发者怎样贡献

- **带来自己的数据。** 已符合标准格式的文件可在本地直接试用。仅字段名不同时贡献映射；格式需解码或支持断点续读时，再贡献 `sources/` 下的读取器。提交一小段合成记录和期望事件即可，用户数据可留在本机。
- **接一个新 benchmark。** 在 `benchmarks/` 实现任务输入、可重置环境与评分，附一条从公开任务取得原生结果的复验。已有宿主继续通过同一个适配器运行。
- **接正在运行的宿主或贡献策略。** 新宿主在自己的适配器目录声明能观察和能写入的节点，附触发、跳过或能力不足的回执。策略可以在仓外独立打包，按项目绑定试跑；希望内置时再提交实现、清单、预期动作和停用样例。分别由宿主负责人或 hzh 对接。[数据与宿主接入](06_数据与宿主接入.md)

## 提交和复验

主仓建立 Git 远端后，团队成员从目标分支创建工作分支，外部开发者可从自己的 fork 提 PR。一个 PR 聚焦一项可独立验证的改动。说明里写清以下四项，供维护者按相同入口复现。

| PR 描述 | 应填写的内容 |
|---|---|
| 要解决什么 | 触发条件、修改前的行为、修改后的预期结果。 |
| 谁负责、改哪里 | 本次入口和路径，受影响宿主、版本，共享变更或关联 PR。 |
| 怎样复验 | 工作目录、环境、命令、合成输入、通过或失败数。失败保留关键断言与堆栈，未跑说明原因。 |
| 如何兼容或回退 | 旧数据、缺能力、重复事件的处理。会写宿主配置或执行动作时，补充停用和回滚结果。 |

下面是可从 `Sklii_RSI_master/` 根目录复跑的**参考原型用例**。使用 Python 3.11+ 和可运行 DSH 测试的 Node。Codex 用例会通过 `PATH` 中的 `python3` 启动合成 CLI，请先激活相应 Python 环境。三条命令分别核对 Messages 转发、Codex 工具回执与续接、DSH 短视图的原文恢复。新主仓提供实现后，PR 还需列出针对自己改动的主仓测试。

```sh
(cd ../Skill_RSI_yangyang/framework && python3 -B -m unittest discover -s tests -p 'test_messages.py')
(cd ../Skill_RSI_chengze/framework && python3 -B -m unittest discover -s tests -p 'test_codex_chatgpt.py')
(cd ../Skill_RSI_hzh/plugins/clbench-submit && node --test context-view.test.mjs)
```
