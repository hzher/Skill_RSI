# 04　可选的小模型训练交接

主框架用任务历史发现策略，可直接把规则做成扩展包。如果希望小模型学会“这一步应该召回、写入、压缩还是跳过”，才将获准的数据交给独立项目 `skill_rl_train/`。主框架持有轨迹与发布记录，训练仓恢复状态、评分并更新权重。成品用户可以独立选择策略包。以下训练接口已存在于相邻仓，跨仓通用导出清单属于本项目的设计。[训练仓说明](../../../skill_rl_train/README.md) · [策略提炼与发布](03_Skill提炼与对照实验.md)

## 手里的数据适合哪条路径

| 你已有的材料 | 可以做什么 | 交接条件 |
|---|---|---|
| 本地会话、用户更正或某一次高分轨迹 | 送 Part 2 分析成功经验与失败原因 | 保留来源和用途。要训练动作选择，还需能比较同一状态的其他动作。 |
| 能恢复到决策前的历史运行 | 在同一恢复点执行候选，得到离线训练用分数 | 保存宿主和环境版本、初始记忆、当时的 query 与公开反馈、原生动作回执和评分窗口。现有历史分支入口支持 DSH 的 Poker 与 Spectrum。[历史分支实现](../../../skill_rl_train/skill_rsi_rl/branch_score.py) |
| 已对所有合法动作评分的数据 | 从 `scored.json` 采样生成 replay，再更新学生模型 | 候选顺序、原生评分、使用授权和 train/dev 划分可校验。已有合格 replay 时直接从校验开始。 |
| 可重置的测试环境和评分器 | 让当前学生在隔离环境中在线采样、得到反馈并训练 | 固定初态与评分器，能为每条轨迹提供原生回执。训练仓提供 DSH、Claude Code、Codex 的 Poker 配置。[三端运行手册](../../../skill_rl_train/doc/04_CL-Bench采集与在线训练.md) |

## 离线交接交什么

框架拟导出一份清单，记录来源窗口、文件相对路径与 SHA-256、用途授权、split、恢复点、宿主版本和评分协议。涉及权重训练的材料须有对应范围的授权。任务及其恢复或分叉出的样本归入同一划分。后来的用户纠正或评分私有标签留在结果侧，学生输入只含当时能看到的证据。训练仓现有读取器使用下表中的格式，通用清单需先适配。[轨迹数据契约](02_轨迹数据契约.md)

| 实际文件 | 生产与校验 |
|---|---|
| `scored.json` | 顶层包含 `dataset_id`、`split`、`score_protocol`、`training_permission`、`authorization_ref` 和 `states`。每个状态记录观察、合法动作 `options` 及同序的 `scores`。各动作从相同初态独立执行，以宿主回执和原生评分得出有限数 `reward`、布尔 `native_success`。真实零分有效，缺分的候选组暂留待补。`load_spec` 检查顶层，`validate_scored_state` 核对候选与分数。[现有读取器](../../../skill_rl_train/skill_rsi_rl/replay_spec.py) |
| replay JSONL | `collect sample` 使用冻结的学生在同一候选集上采样。首行记录来源、checkpoint、tokenizer、split 和采样设置，后续各行保存状态、候选、行为概率和采样结果。`verify_replay` 核对拆分、回报变化等条件，训练时再用当前 tokenizer 检查输入一致性。[采样实现](../../../skill_rl_train/skill_rsi_rl/collect.py) · [校验入口](../../../skill_rl_train/skill_rsi_rl/verify_replay.py) |

例如，在同一个报表任务中，学生可以选择直接继续，或先召回保存的字段单位。两条路径各自在同版本环境中执行到相同截止点。若只执行了直接继续，另一个动作尚无可用分数。可以补跑该分支后再封存数据。下例在 `skill_rl_train/` 中以 Python 运行，演示真实接口怎样生成和应用候选，无需模型或 GPU。[动作接口](../../../skill_rl_train/skill_rsi_rl/contracts.py)

```python
from skill_rsi_rl.contracts import apply_action, propose_options

memory = {"latency_unit": "v4: seconds"}
options = propose_options("latency unit?", [], memory)
assert options[0]["action"] == {"op": "noop"}
recall = next(item["action"] for item in options if item["action"]["op"] == "recall")
updated, evidence = apply_action(recall, memory)
assert updated == memory and "v4: seconds" in evidence
```

## 在线训练和回接

在线模式每轮冻结学生版本，在同一环境种子和初始状态下，用独立工作区采样多条完整运行。核实每步所选动作确实应用、同组得到可比较的环境奖励，封存批次后才更新下一轮权重。用户电脑上的真实任务可选择供 Part 1 记录；需要在线训练时另接可重置、能隔离副作用的测试环境。[在线循环](../../../skill_rl_train/skill_rsi_rl/online.py) · [在线批次校验](../../../skill_rl_train/skill_rsi_rl/rollout_batch.py)

训练完成后，在训练和调参均未使用的完整任务上，对照原生、未训练、离线训练、在线训练四种配置。记录首次动作正确率、任务完成率、额外读取和推理成本。若作为策略包发布，在制品清单固定权重或推理服务版本、适用宿主和回退方式。包的用户按项目试跑或启用。训练环境、权重和私有数据由训练仓与数据持有方管理。[训练与比较命令](../../../skill_rl_train/README.md) · [开发分工与 PR 规范](05_开发分工与PR规范.md)
