# Skill_RSI · 让 AI 助手在长任务里用对记忆

一个项目做了三天，助手还能记得哪条结论有效、哪一步已经做过、哪份资料值得再读吗？**Skill_RSI 希望从真实任务中找出这些规律，把有用的做法做成可单独安装的扩展包，让下一位用户也能受益。**

[看使用例子](#可以怎样试用) · [看开发例子](#开发者从哪里下手) · [看未来蓝图](#未来蓝图) · [查分工与提交流程](05_开发分工与PR规范.md)

## 一个跨天的接口迁移

周一，助手查到旧接口返回的耗时是 `1500` 毫秒，于是在报表中除以 1000，显示为 `1.5` 秒。周二，用户升级了接口，新版已经直接返回 `1.5` 秒。周三恢复工作时，助手找到了周一的笔记，又除了一次，报表便写成了 `0.0015` 秒。

这里有两个值得开发者追查的问题。**旧单位从哪一步开始失效？助手做换算时，究竟看到了哪一版定义？** 如果工具已经返回新版、但恢复后的模型输入丢了它，应当修复信息交付。如果模型看到了新版仍套用旧公式，就要检查执行前的核验。只记一条“读取过项目记忆”，无法区分这两种情况。

> **我们手上的起点**  
> 一份已有 DSH 报告包含 100 次执行，来自 20 个独立实例，记录了 465 次主任务模型调用，却没有观测到压缩事件。它能帮我们找重复调用。要研究“压缩后忘了用户的更正”，下一批就要选真正经历压缩和恢复的任务。这是 Part 1 为什么同时记录行为和观测缺口。[本地批次汇总](../../../trajectory-lab/reports/clbench-dsh-100/summary.json)

## 从一条轨迹到一个能安装的包

```mermaid
flowchart LR
    A["记录一次任务<br/>输入、动作、结果"] --> B["比较任务历史<br/>找到成败分歧"]
    B --> C["实现候选策略<br/>在新任务上检验"]
    C --> D["发布扩展包<br/>用户按项目启停"]
```

| 谁来做 | 在接口迁移例子里要做什么 | 交给下一步什么 |
|---|---|---|
| **Part 1 · 记录** | 从 DSH、Claude Code、Codex 或用户提供的历史中，连接用户更正、工具返回、下一次动作和报表结果。看不到实际模型输入时，保留这个缺口。 | 能回查原件的一段任务记录，包括时间、对象、来源版本和可见范围。 |
| **Part 2 · 发现与验证** | 可调用大模型比较正确换算、错误换算、无需复查三种历史，提出“用旧结论前核对来源修订”的算法，再到独立项目检验。 | 有版本、触发条件、反例、开销和适用宿主的策略包。 |
| **产物使用者** | 在自己的项目选一个包，先看它在哪些步骤会介入，再决定提示、自动执行或停用。 | 任务能否完成、关键动作是否正确，以及少了多少重复操作。使用成品无需交出自己的历史。 |

这里的 *harness* 指调用模型和工具、管理会话的宿主软件。扩展可以是一份 Skill、一个 MCP 工具、一个 hook，也可以是宿主插件、网关改造或跨多个执行节点的中间件。比如同样要缩短一份长日志，DSH 可以在主调用前调整视图，Claude Code 拟用工具执行后的回调，Codex 则先从自有 MCP 工具的返回值做起。策略相同，接入位置由宿主能力决定。[三种宿主的适配设计](01_总体方案与架构.md#同一个策略包怎样接到三种宿主)

## 可以怎样试用

| 遇到的情况 | 首版打算怎样帮助用户 | 怎么知道真的有用 |
|---|---|---|
| **长日志排错。** 几千行输出里只有几行编译错误，助手反复重读全文。 | `tool-result-view` 先给错误片段、原文行号和可展开引用。若第一次摘取遗漏线索，仍可读取原件。 | 错误能定位，末尾的关键行也能找回，同时少读了多少无关内容。 |
| **跨天继续。** 恢复任务后沿用旧接口单位。 | `constraint-check` 在换算前核对对象和修订。版本已变就定点查证，当前已有可靠的新定义就跳过。 | 第一次换算是否正确，来源未变的任务是否多做了检查。 |
| **同项目内换工作方式。** 开发者临时想看原始日志，但仍希望检查旧约束。 | 只关掉日志包。从宿主确认的下一生效边界开始，新结果恢复原生展示，核验包继续工作。 | 另一个包的下一次回执仍在；保留期内，旧日志引用也能打开。 |
| **团队只有旧会话。** 想弄清某类返工原因，项目还没有接入适配器。 | 从授权的历史导出开始，保留更正与后续动作的引用。材料不足时，把原因列为待验证假设。 | 不接 benchmark 也能读入记录；补充同类成功任务后能比较分歧。[数据接入](06_数据与宿主接入.md) |

**一个调用例子。** 下列是首版拟提供的命令。假设 DSH 适配器已配置，本机已安装两个包。第一行只试跑日志策略，第二行让核验策略实际运行；核对过效果后，可把日志包切到执行模式，也可单独停用。

```sh
skill-rsi project enable tool-result-view@1.0.0 --host dsh --project . --mode shadow
skill-rsi project enable constraint-check@1.0.0 --host dsh --project . --mode apply
skill-rsi project disable tool-result-view --host dsh --project .
```

## 开发者从哪里下手

| 想贡献什么 | 最小开发例子 | 第一条验收 |
|---|---|---|
| 一个宿主能力 | 为 Claude Code 增加工具返回回调，用同一份合成日志覆盖完整返回和缺字段两个情况。 | 区分“工具返回了什么”和“后续主请求是否收到了它”。 |
| 一种数据格式 | 把本地导出中的 `session`、`seq`、`kind` 映射为会话、顺序与事件类型，保留原文件位置。 | 重复导入同一行只产生一个事件，另一个项目的同名会话仍可区分。 |
| 一个策略 | 从更正单位的历史中提炼版本规则，准备“已变、未变、当前已可见”三个例子。 | 分别得到重验、复用或跳过，并能说明依据的来源。 |
| 一个 benchmark | 准备公开题面与独立评分器，在同一初态分别启用和停用策略。 | 更换私有答案只影响评分，执行器和发现模型看到的输入一致。 |

**把经验写成可测的代码。** 假设当前窗口没有已经核实的新定义。下一步如果要用旧单位，就比较当时与现在的接口修订；如果只是修改报表标题，连这次查询也可以省掉。下面的 Python 例子可独立运行。

```python
def needs_recheck(uses_unit, saved_revision, current_revision):
    if not uses_unit:
        return False
    return current_revision is None or saved_revision != current_revision

assert needs_recheck(True, "v3", "v4")       # 单位要用于换算，接口已经升级
assert not needs_recheck(True, "v4", "v4")   # 同一来源、同一修订，复用已核实的单位
assert needs_recheck(True, "v3", None)       # 当前修订未知，先查证
assert not needs_recheck(False, "v3", "v4")  # 改标题不涉及单位
```

**今天可调用的参考例子。** 在本地完整的 `memorax/` 工作区，从 `Sklii_RSI_master/` 根目录运行，需 Python 3.11+。脚本化模型连续处理两个任务，第二个任务要读到第一个任务生成的 Skill。测试通过说明跨任务复用这条链路可工作；真实长任务上的净收益另做独立对照。[用例与断言](../../../Skill_RSI_hzh/framework/tests/test_framework.py)

## 未来蓝图

| 阶段 | 交付到用户手上 | 进入下一步的依据 |
|---|---|---|
| **记录与复现** | 一个本地历史入口和一条 DSH 原生记录链，覆盖成功、失败及无需介入的任务。 | 从一次错误动作能回查此前可见的证据。无法确认的字段如实标记。 |
| **首版双包** | 通用安装入口、项目绑定、日志展开包和旧约束核验包。 | 用户能独立试跑、启停和回退；在留出的完整任务上，分别公布两包的单独和组合效果。 |
| **三端与外部贡献** | 将验证过的能力逐端接入 Claude Code、Codex，接收外部数据源、宿主和评分器。 | 换一套数据或换一个宿主，可继续使用同一事件契约，并能查到各宿主的实际支持范围。 |
| **更深的执行控制** | 为确实需要跨阶段状态的策略提供多节点中间件；对可恢复的环境再试验检查点、分支和可选小模型策略。 | 计入展开、重试、模型和子任务的总成本后，在新项目仍有收益。训练在独立仓进行。[训练交接](04_离线训练交接.md) |

发布时分别回答四个问题：恢复后是否更稳、关键动作是否更准、同预算下是否完成更多任务、每次成功少花了多少重复劳动。首版双包及三端效果目前属于开发目标。[提炼与对照实验](03_Skill提炼与对照实验.md) · [按宿主选用指南](../../README.md#三种宿主)
